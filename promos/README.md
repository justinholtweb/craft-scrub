# Plugin Store promo images

Marketing images for the Scrub listing on the Craft Plugin Store, rendered in the same theme as
the plugin's marketing page at
[justinholt.com/plugins/craft-scrub](https://justinholt.com/plugins/craft-scrub).

## Building

```bash
./build.sh          # all slides
./build.sh "2 5"    # just slides 2 and 5
```

Output lands in `out/` as `scrub-promo-N.png`, 1920×1080 (rendered at 2× in headless Chrome, then
downsampled so the type stays crisp).

## The screenshots

`shots/` holds four real control-panel screens, captured from the shared harness at
`~/Sites/plugin-testing` with Scrub installed on the Pro edition. They are committed, so the deck
builds from a clean clone.

Every number in them is real and they agree with each other: the same run appears as *31 matches
in 12 places* in the preview, in the history and on the run detail, because it is the same run.
They also agree with the interactive demo on the marketing page, which uses the same Acme Ltd →
Acme Inc story.

To re-shoot them:

1. Start the harness and seed the content — `seed-harness.php` is idempotent and belongs at the
   harness root:

   ```sh
   cp promos/seed-harness.php ~/Sites/plugin-testing/
   docker exec -w /var/www/html ddev-plugin-testing-web php seed-harness.php
   ```

   Use `docker exec`, not `ddev exec`: the harness's web container takes longer to pass its health
   check than ddev waits, which turns into a start → timeout → recreate loop.

2. `docker exec … php craft users/impersonate admin` for a one-hour CP login URL.

3. Drive the browser with Playwright, not headless Chrome — the CP polls, so network never goes
   idle and headless Chrome never exits. Strip `#global-sidebar`, `#global-header`,
   `#global-footer`, `#notifications`, `#upr-root`, `#queuebert-bar` and any sibling plugin's
   panel *in the page* before capturing, and set the background to the CP's own `#e4edf6` so a
   cropped edge never shows black.

4. The capture is 0.875× of CSS pixels, so zoom trades layout width for real resolution:
   `document.documentElement.style.zoom = 1.6` with `#main` at `1728 / 1.6 = 1080px` fills the
   frame at an effective 1.4×, which is comfortably sharper than the ~1080px the deck displays
   them at.

**Put the harness back afterwards.** It is shared. Undo the run (`craft scrub/run/revert <id>`)
and delete any saved rules — a real-time or on-save rule left enabled there will quietly rewrite
other people's test content on every save.

## Editing

Everything lives in `slides.html` — one `<section class="slide">` per image. The palette and fonts
are the plugin site's: accent `#53A5A3`, Jersey 20 for display, Inter for body.

Note that `.panel` and `.term` are both absolutely positioned as **direct children of the slide**.
Nesting `.term` inside `.panel` squeezes it into a one-word-per-line column. `.sheet` is a plain
block and does go inside `.panel`.

`assets/` holds the fonts and two icon files:

- `icon.svg` — the app icon, used for the cover mark and the footer lockup. Copy it from
  `../src/icon.svg` whenever the icon changes.
- `watermark.svg` — the brush as **line art**, with the plate stripped and the mark scaled past
  the viewBox. The usual advice is to strip the icon's frame, but that is not enough here: the
  brush's head is one large flat area, and at watermark scale its straight edges close it into a
  hard-edged box across the slide just as a frame would. An outline has no interior to close.

`fonts.css` is generated by `build.sh` (the woff2 files are base64-inlined so Chrome's `file://`
origin rules can't block them) and is not checked in.
